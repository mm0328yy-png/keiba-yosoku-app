# keiba-yosoku-app

前走の結果を「着順・着差だけ」で見るのではなく、**前が詰まった・出遅れた・接触を受けた**
といったレース中の不利（トラブル）まで加味して、馬の真の実力を分析する競馬予想アプリです。

「実力はあったのに展開が向かず負けただけ」なのか「実力どおり負けた」のかを区別することを
目的としています。

## 現在できること（MVP）

- 前走成績（着順・着差・不利の内容）を手入力で登録
- 不利の種類・発生タイミング・深刻度から「不利補正スコア」を算出
- 額面どおりの着順評価（額面スコア）と、不利を加味した「真の実力スコア」を並べて比較
- 大きな不利を受けて着外に敗れたケースを「不運な敗戦」として自動フラグ
- 馬ごとに複数レースを集計し、真の実力スコア順にランキング表示
- 出走馬を選んでレース単位で単勝・複勝・ワイド・3連複の買い目を提案（回収率重視）
- 予想を記録し、実際の結果（1〜3着）を入力すると券種ごとの的中率を自動集計

### スコアリングロジック

`src/lib/analysis.ts` に実装。ロジックは以下の通り（数値は調整可能な定数）:

1. **額面スコア**
   - 2着以下: `100 - 着差(馬身) × 2` （着差が大きいほど減点、0〜100にクランプ）
   - 1着: `100 + 勝ち馬身差(2着との差, 馬身) × 1` （圧勝ほど加点、100〜110にクランプ）
     - この加点が無いと「勝った馬は一律100点」になり、僅差の勝利と圧勝が区別できない
2. **不利補正** = 不利ごとの「深刻度に応じた加点」×「発生タイミングの重み」の合計
   - 深刻度1〜5: 数字が大きいほど非線形に大きく加点
   - タイミング: 直線 > 最終コーナー > 向正面 > スタート直後（直線の不利ほど致命的で評価が高い）
3. **真の実力スコア** = 額面スコア + 不利補正（0〜110にクランプ）
4. 着順4着以下 かつ 不利補正が一定以上 → 「不運な敗戦」としてフラグ

ロジックの妥当性は `src/lib/analysis.test.ts` のテストで検証しています。

### レース予想・買い目ロジック

`src/lib/predict.ts` に実装。出走馬同士を「真の実力スコア」で比較し、
的中率より回収率を重視した買い目を提案します。

- **単勝・複勝**: 人気馬（1番人気）ではなく「穴」（4番人気以下で実力スコアが最も高い馬）を本命視
- **ワイド**: 人気馬1頭 + 穴馬1頭。穴の選定は次の優先順で決まる
  1. 実際のワイドオッズ（組み合わせそのものの配当）が8倍以上ある入力済みの組み合わせ
  2. なければ、単勝オッズが8倍以上の馬（簡易的な代用）
  3. それも無ければ、4番人気以下プールで代用
  - 単勝オッズだけでは実際のワイド配当の高さを正確には予測できません（人気馬と組むと
    配当が圧縮されるため）。可能な限り実際のワイドオッズを入力することを推奨します。
- **3連複**: 真の実力スコア上位3頭のBOX

### 予想の記録・的中率チェック

`src/lib/predictionLog.ts` に実装。「この予想を記録する」ボタンでその時点の買い目を
ブラウザの `localStorage` に保存し、後から実際の1〜3着を入力すると、券種ごとに
的中/不的中を自動判定して集計します（サーバーには送信されません、端末内のみの保存）。

## データソースについて（今後の拡張）

現時点では前走データは手入力です。将来的には **JRA-VANデータラボ** の有料API
（JV-Link / JRA-VAN NEXT）から自動取得することを想定していますが、以下の理由で
今回のMVPには含めていません。

- JRA-VANデータラボの利用にはデータラボID（月額課金）の契約が必要
- 公式のJV-LinkはWindows専用のCOMインターフェースで、本アプリのようなWeb/Node環境から
  直接呼び出すには中継サーバー（Windows上でJV-Linkを叩き、結果をこのアプリのAPIに
  送るブリッジ）が別途必要

契約・環境が用意でき次第、`src/lib/sampleData.ts` を置き換える形でデータ取得層
（例: `src/lib/dataSources/jraVan.ts`）を追加し、取得したレース結果を
`PastPerformance` 型に変換して取り込む想定です。
